## Looked at and decided it was not a defect

- **`load_dotenv()` priority.** Its default is `override=False`, so real environment variables already win over `.env`. I kept it and made the intent explicit (`override=False`).
- **Plain `def` handlers.** FastAPI runs them in a thread pool, and `MongoClient` is thread-safe and pooled, so concurrent requests are fine. Async with Motor would not add correctness here. Race safety comes from the database (unique indexes, conditional updates), not from the handler type.
- **String comparison of dates.** `YYYY-MM-DD` strings sort the same way as the dates they represent, so `$gte` / `$lte` on `date` is correct. That holds once the input format is validated (#24).
- **Default shift `09:30-18:30`** matches the contract defaults.
- **`doc.pop("_id")` after `insert_one`** works. I replaced it with explicit serialisers so no internal field can leak by accident.
- **Reusing the helpers.** I did not reuse them as-is (see #4-#8). The new helpers take the attendance date and the employee's shift explicitly, so punch-in, punch-out and PATCH share one implementation of R1-R5.
